Part 4: Optimization & Reward Math

Finding the Line (Code)

Optimizing tracking using Windowed Searches.

To calculate the lateral_error, the simulator has to answer a basic question 50 times a second: "Out of the 10,000 waypoints that make up the track, which one is closest to the car right now?"

A Global Search across all points is $O(N)$ and would melt the CPU. In track_manager.py, the developers wrote a highly optimized $O(K)$ search algorithm. Instead of checking the whole track, the math relies on the fact that cars don't teleport. If the car was closest to Waypoint #400 a millisecond ago, it must be somewhere near #400 now.

TRACK_MANAGER.PY 
# Windowed Search: Look +/- 50 waypoints around last known index
window_size = 50
offsets = torch.arange(-window_size, window_size + 1)
search_indices = (self.last_indices.view(-1, 1) + offsets) % num_wps

candidate_wps = self.waypoints[search_indices][:, :, :2]
candidate_dists = torch.norm(pos[:, None, :2] - candidate_wps, dim=2)
min_dists, best_in_window = torch.min(candidate_dists, dim=1)

# Fallback to Global Search for any envs that teleported (e.g. resets)
global_search_mask = min_dists > 2.0
if global_search_mask.any():
    global_dists = torch.cdist(pos[global_search_mask, :2], self.waypoints[:, :2])
    best_global_idx = torch.argmin(global_dists, dim=1)
PLAIN ENGLISH

Create a small search "window" of just 100 points (50 behind, 50 ahead).

Center this window on whatever waypoint the car was closest to during the previous physics frame.

Gather the exact X,Y coordinates of just those 100 candidate waypoints.

Calculate the distance to those 100 points, and find the absolute closest one.

Wait — did the car crash and respawn at the start of the track? We check if the "closest" point is more than 2 meters away. If so, the car must have teleported!

Only for cars that teleported, run the slow, expensive Global Search to find them again.
