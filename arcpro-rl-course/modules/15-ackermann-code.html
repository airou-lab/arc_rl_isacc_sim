Part 5: Action Kinematics

Ackermann Steering Math (Code)

Implementing Kinematics in actions.py.

Let's look at how the bicycle model is implemented in PyTorch tensors inside actions.py to control the F1Tenth rover.

ACTIONS.PY (Ackermann Mapping) 
# Calculate the turning radius (R) from steering angle (delta)
turn_radius = self.wheelbase / torch.tan(torch.abs(steering) + 1e-6)

# Calculate specific inner/outer wheel angles
inner_angle = torch.atan(self.wheelbase / (turn_radius - self.half_track))
outer_angle = torch.atan(self.wheelbase / (turn_radius + self.half_track))

# Map to left and right joints based on turn direction
left_angle = torch.where(steering > 0, inner_angle, -outer_angle)
right_angle = torch.where(steering > 0, outer_angle, -inner_angle)
PLAIN ENGLISH

Calculate the imaginary circle the car is turning around (using the length of the car). Add $10^{-6}$ to prevent dividing by zero when going straight.

Calculate the sharper angle for the inner wheel.

Calculate the wider angle for the outer wheel.

If turning left, the left wheel is the inner wheel. If right, it's the outer wheel.

Action Fusing (Velocity Control)

Similarly, the policy outputs separate throttle and brake commands, but the rigid body joints require a singular angular velocity target $\omega$. We fuse them mathematically in CombinedDriveAction.

ACTIONS.PY (Fusing) 
throttle = torch.clamp(actions[:, 0:1], 0.0, 1.0)
brake    = torch.clamp(actions[:, 1:2], 0.0, 1.0)

drive = throttle * (1.0 - brake)
PLAIN ENGLISH

Clamp the AI throttle to exactly 0 to 1.

Clamp the AI brake to exactly 0 to 1.

Fuse them using multiplication! If brake is 1.0, the inverse is 0.0, so the drive is immediately cut to 0 regardless of throttle. This guarantees the AI can never drive backwards if it panics and mashes both pedals.
